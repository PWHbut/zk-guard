# zk-guard

知课客户端的**远端配置仓库**。只放公开的配置 JSON 与操作文档，**不含任何用户数据，也不含任何明文密钥**。

| 文件 | 作用 | 谁读 |
| --- | --- | --- |
| `guard.json` | **控制策略**：全局开关 + 按版本规则 + 默认策略 + 签名（`enabled` / `minBuild` / `default` / `rules` / `rev` / `auth` / `authV2`） | 客户端（每次启动、回前台、每 60 秒） |
| `hot.json` | 界面热更新补丁：`v` / `css` / `js` / `flags` / `note` / `minBuild` / `maxBuild` / `auth` | 客户端（启动时、回前台） |
| `key.json` | 控制台密钥的 **SHA-256 哈希**（只有 `hash`，没有明文） | 控制台（自校验操作员输入的密钥是否正确） |
| `index.html` | 控制台页面（GitHub Pages，写入令牌只存在本机浏览器） | 操作员（浏览器） |
| `README.md` | 本文件：仓库总览 | 人 |
| `KEY.md` | **[密钥是什么 · 存放位置 · 使用与轮换](KEY.md)** | 人 |
| `POLICY.md` | **[版本控制协议：字段 / 优先级 / 签名 / 兼容矩阵](POLICY.md)** | 人 |
| `GUIDE.md` | **[控制台使用说明（详细）](GUIDE.md)** | 人 |

控制台入口： https://pwhbut.github.io/zk-guard/

> **明文密钥不在这个仓库**。它在**私有**源码仓库 [`PWHbut/zhike`](https://github.com/PWHbut/zhike) 的 `CONSOLE_KEY.txt`（只有仓库所有者可见），以及你本机的 `/workspace/CONSOLE_KEY.txt`。本仓库只有哈希与完整的位置说明。原因见 [KEY.md](KEY.md) §2。

## 快速理解

- **全局状态**：`enabled: false` 让全体客户端显示「连接不上服务器」；设回 `true` 即恢复。用户端看到的和一次普通网络故障没有区别。
- **按版本控制（v5.7 新增）**：`rules` 按客户端 `versionCode` 区间匹配（顺序优先），没命中就走 `default`。**把 `default` 设成停用、给当前版本加一条放行，之后发布的任何新版本都会自动落入停用——控制台不用跟着升级**。开区间（`maxBuild: 0`）可直接覆盖未来版本。
- **控制台只用来防止软件被滥用**：不做用户管理、不收集任何数据、不影响本机已缓存的内容。
- **生效时间**：客户端在启动时、回到前台时、以及每 60 秒读一次 `guard.json`；状态切换最迟 1 分钟覆盖全部在线设备。取不到时退避到 3 / 9 / 27 分钟，并一律**按可用处理**。
- **配置源**：客户端与控制台都从 **4 个源并发读取并取最新**（GitHub API、jsDelivr、Fastly jsDelivr、raw.githubusercontent.com），按 `rev` / `updated` 判断新旧。单个 CDN 缓存旧值不会让状态回退；`api.github.com` 匿名限流时 CDN 自动承接。
- **双代签名**：`auth` 给旧客户端验（`enabled:false` 时），`authV2` 给 v5.7+ 客户端验整份策略。把控制指令改成「停用」必须带合法签名，否则客户端忽略——公开仓库被误改、被别人提交，都无法让全体用户掉线。
- **源码仓库私有**：业务源码、客户端内置的验签常量 `GUARD_SECRET` 都在私有仓库 [`PWHbut/zhike`](https://github.com/PWHbut/zhike)。本仓库是公开的，**任何明文密钥都不允许写进来**。

## 兼容性边界

| 客户端版本 | 能被怎样控制 |
| --- | --- |
| v5.6 及更早（versionCode ≤ 57） | 只认全局开关 `enabled` + `auth`，**停止 / 恢复所有用户有效**；读不懂按版本规则，无法精确控制（历史版本已发行，代码无法追加能力） |
| v5.7 及以后（≥ 58） | 全局开关 + 按版本区间精确控制 + 默认策略兜底 + 提示升级 |
| 未来新版本（≥ 59） | 无需控制台改动，由开区间规则或 `default` 自动覆盖 |

完整字段、判定优先级、签名公式与场景配方见 [POLICY.md](POLICY.md)。
